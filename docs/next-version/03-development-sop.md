# 下一版开发 SOP：先把一个垂类做深

日期：2026-09-13。适用：个人开发者主导、小团队协作的验收助手下一版。以下是执行计划，勾选状态见另一份清单。

本版优先服务“持续交付小型 Web 记录管理工具、缺少专职测试的开发者或负责人”。该用户画像仍需访谈验证。先解决状态保存与文件导出交付验收，不同时扩展 RAG、AIGC、真机和全行业。

## 意图流

| 使用者意图 | 产品要转成什么 | 用户看到什么 | 下一环节 |
|---|---|---|---|
| 我要交付这个版本 | 本轮目标、必须项、版本与终点 | 简短范围，冲突时才追问 | 建立可检查标准 |
| 帮我确认结果对不对 | 主路径、异常输入、最终产物 | 检查状态与缺失条件 | 实际执行并判断 |
| 告诉我哪里不符合 | 同一标准下的预期、实际和证据 | 问题、位置、触发操作 | 给出处理与复查条件 |
| 修好后确认没再出问题 | 修复版本与原问题关联 | 原问题结果及相关回归 | 记录完成或保留问题 |
| 下次别让我重复解释 | 有适用范围的纠正案例 | 哪项检查被改变、为什么 | 下一任务验证增益 |

## 开发者按这个顺序执行

| 步骤 | 具体做什么 | 产出 | 进入下一步的条件 |
|---|---|---|---|
| 1 定人和场景 | 找实际交付记录管理工具的人，问最近一次交付、原有检查办法、最常漏项及投入；先做 3 次探索访谈 | 具体任务样本、用户原话、未证实假设 | 能指出一个重复发生的任务；3 次访谈只是起步，不作市场规模结论 |
| 2 跑强基线 | 选人工清单、现有测试、接工具的大模型中实际最可行者，完成同一质量要求的检查 | 基线操作、正确结果、人工分钟、等待、费用 | 不将只聊天的模型当作弱对手；已有办法更好时允许改成插件或缩小方向 |
| 3 冻结本批目标 | 定义“同一阅读清单导出问题的连续修复”；写必须项、范围、原始版本与独立预期 | 一页验收契约与样本集 | 标准先于改代码冻结；无明确标准先补证 |
| 4 画最短交付路径 | 输入目标→计划→实际文件→问题→开发交接→原标准复查；标前置依赖 | 流程表、数据对象关系、支持矩阵 | 每项功能能对应用户终点；新增想法先进入候选表 |
| 5 先补连续证据 | 复用已有执行器与报告，关联问题 ID、检查 ID、标准版本、程序版本、修改提交与前后文件 | 一条可回查的修复链 | 实际修改同一项目；不能把切换预置正常样例写成修复完成 |
| 6 再补建议 | 根据已确认差异说明影响、定位方向、可选动作、未知项、复查范围 | 可交给开发工具的问题包 | 原因假设与事实分开；用户采纳不直接算有效 |
| 7 独立验收助手 | 用预先确认的正常、故障、缺文件、错控件、标准冲突与旧历史失效样本检查 | 误报、漏报、未知、受阻、错误归因记录 | 核心结果有独立答案；缺证据不被记为通过 |
| 8 做同类迁移 | 用未参与规则编写的记录管理项目，记录新接入和修改脚本的人工投入 | 迁移结果、定制项、复用项和成本 | 计划先验证 3 个同类项目；每个结果单列，不能用平均数掩盖失败 |
| 9 测真实使用收益 | 邀请未参与实现的人独立完成任务；使用顺序交替，保留求助与误报处理 | 质量、净人工投入、返工和解释次数对照 | 先做 5 人探索试用；样本不足只报观察，不宣称普遍提效 |
| 10 发布与路演 | 在实际域名检查首页、任务、文件、报告、视频；用一个案例讲需求到结果 | 可访问入口、完整案例、发布回执、已知限制 | 新访客能独立打开和使用；截图、接口 200、平台运行中均不能单独代替验收 |
| 11 决定下一批 | 按预设指标决定继续做深、改变形态或扩展一个相邻能力 | 决策记录与下一批任务书 | 当前垂类的正确性、迁移、使用收益三道门槛均有证据后才扩类 |

前三步优先完成：**拿到真实任务 → 跑原有办法 → 冻结一个连续修复目标**。已有公开案例继续保留用于演示。

## 谁负责判断

| 环节 | 系统/AI 负责 | 开发者或独立复核者负责 |
|---|---|---|
| 理解材料 | 整理候选目标、标准来源与冲突 | 确认会改变交付结果的关键冲突 |
| 执行 | 程序约束动作、范围、预算并保存实际证据 | 提供可运行环境和必要授权 |
| 判定 | 字段、状态、文件采用确定性核对；语义判断输出有依据的候选结论 | 对独立答案、疑难误报漏报进行复核 |
| 修复 | 输出问题包与复查范围 | 开发者/开发工具改代码，助手复查结果 |
| 取舍 | 说明选项、约束与未知代价 | 负责人决定交付范围、预算与是否扩展 |

## 每一批的交付清单

- [ ] 一个明确的用户任务和原有做法。
- [ ] 冻结的质量门槛、主指标与最小有意义改善值。
- [ ] 可运行入口和一条连续证据链。
- [ ] 正常、故障、缺证据、标准变化的检查结果。
- [ ] 接入、维护、解释、误报处理与复查的实际人工投入。
- [ ] 已做、未做、范围外以及下一批取舍。

以上为可复用空模板，不代表当前所有项未实现。当前完成情况见 [版本清单](04-iteration-checklist.md)。

## 五分钟路演安排

| 时间 | 讲什么 | 展示依据 |
|---|---|---|
| 0:00–0:40 | 谁在什么交付环节遇到什么问题 | 一个具体任务，不从功能分类开场 |
| 0:40–1:20 | 原来怎么做，本工具接手哪部分 | 原有流程与产品意图流 |
| 1:20–3:20 | 目标、检查、实际文件、问题和复检 | 主讲一个完整案例；其他功能放附录 |
| 3:20–4:20 | 已证明什么、哪些还未测得 | 产品质量、助手准确性、用户收益分开 |
| 4:20–5:00 | 下一版先补哪一条证据 | 连续修复→同类迁移→用户收益，之后才扩类 |
