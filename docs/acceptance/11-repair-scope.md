# 控件缺失与检查范围变化

日期：2026-09-16。本批针对基础静态网页的连续复检，不扩展业务类型。

实际发现并修复的问题：一次修复检查完成后，再移除某条检查项，复检摘要仍沿用“原标准通过”的旧结论。现在每次读取复检摘要，都会在核对原始证据后比较当前计划与实际执行计划；不一致时显示“执行后检查范围或标准发生变化”，提示重新建立任务。原执行记录仍保留，并分别列出执行标准与当前计划的指纹。

| 场景 | 修改前实测 | 修改后实测 |
|---|---|---|
| 原输入控件被移除 | 该路径未验证，没有悄悄移除 | 同样保留；文字修复通过不能替代输入路径 |
| 运行前移除原文字检查 | 范围与原标准不一致，不确认修复 | 同样保留未验证 |
| 运行通过后移除原文字检查 | 仍显示修复通过 | 改为范围/标准已变化；撤回当前摘要中的通过结论 |

使用者不需要额外填写表格。按原标准修复时保留原检查项；确需改变标准时建立新任务，旧结果仅作为旧版本记录。

验证：73 项既有模块测试通过；三个实际本机上传、执行、修改范围场景按相同设置前后各运行一组。原控件缺失的执行尝试为 1 次后保留未验证，其余已执行检查各 2 次；不能把它写成所有路径重复通过。网页和 Codex 交接均与当前状态一致，运行后改范围的案例原来的 3 条检查记录保留。重启后实际 PDF 导出仍为标准已变化；4 页文字、前后标准指纹与全部页面渲染均已核对。

原始对照保存为本地 01（观察修改前行为）与 02（修复后断言）两组。复现：`node audit/check-repair-scope.mjs <新的输出目录>`；只观察现状可加 `--observe`，观察模式本身不表示满足修复标准。

本批证明受控场景的状态修正，不是通用控件识别准确率，也没有真人省时或减少返工测量。中断恢复的执行完成逻辑与业务/下载跨快照仍待验。
