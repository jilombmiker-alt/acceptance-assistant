# 重传时更新当前页面的缺项提示

日期：2026-09-16。本批修复一个旧提示残留问题：按原标准重传时，原任务的缺项说明被整体复制，新版本已观察到的资源或输入定位缺项没有同步到首页。

修复后，系统重新整理当前上传版本的扫描缺项、未读取请求及原输入定位的观察情况。原目标、输入、预期、次数和检查动作继续冻结。资源补回后撤回过期提示，不让上轮缺项一直跟随新版本。

## 实际核对

| 阶段 | 实际条件 | 结果 |
|---|---|---|
| 原任务 | 有脚本和样式，脚本生成输入框；页面文字与明确预期不一致 | 四项各两次检查，形成原任务依据 |
| 修改前的重传问题 | 新上传遗漏脚本和样式 | 观察到两个未读取请求、未观察到输入框，但首页警告为空 |
| 修复后的相同重传 | 仍遗漏同样两个资源 | 首页直接提示资源路径，当前计划保留原输入检查及定位缺项 |
| 实际执行缺资源版本 | 请求未获允许，未扩大读取权限 | 四项各取得一次未验证记录，整体修复未确认 |
| 补回脚本与样式后重传 | 重新观察到原输入，资源读取条件恢复 | 旧警告撤回，原四项各两次通过，前后标准指纹一致 |

最后一阶段通过的范围是本轮四项基础检查。上一轮未取得完整验证结果，因此不能据此宣布“原业务缺陷已完成修复”；整体比较仍保留未确认。资源观察提示也不能单独证明产品代码存在缺陷。

## 用户怎么处理

看到未读取请求时，先核对选择的代码目录是否包含相关文件，以及项目是否依赖当前不支持的请求。补齐后重新选择文件夹并按原标准复检。系统重新观察当前版本，无需用户逐条判断旧提示是否还适用。

输入提示表示本次观察没有对应上原定位，可能需要继续核对实际页面；它不自动删除原检查，也不自动认定业务失败。只核对活跃计划中的输入项，已移除的输入检查不会因此重新加入。

101 项模块测试通过，包含部分输入缺失、恢复后清除旧提示、保留原终点约束和提示脱敏。实际三阶段审计通过，首页已打开并展开核对四项原标准；HTML 报告包含当前资源提示。复现：`node audit/check-snapshot-observation.mjs <新的输出目录>`。[脱敏摘要](evidence/snapshot-observation.json)。

本批没有增加任意业务模板、扩展网络权限或改变结果判定。没有覆盖所有资源失败原因、所有定位方式或独立真实项目；未测量人工节省。PDF 与 Codex 尚未新增这类观察提示段落，本批也没有重新验收它们。下一轮先补相同观察缺项的交接表达，再继续当前垂类深度。魔搭新版本仍待发布。
