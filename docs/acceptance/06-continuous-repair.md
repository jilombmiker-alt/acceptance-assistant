# 同一阅读清单项目的连续修复验收

日期：2026-09-16。受控已知问题，当前通过开发者审计入口运行；尚未接入用户任务页的自动修复关联。

## 本次实际改变

在独立阅读清单副本中，导出原先把每条书目的 read 强制写为 false。首次检查完成后，在同一目录修改 app.js，使导出保留当前 read；没有切换预置正常版网址。冻结的标准和 11 个检查项不变，每个版本每条路径运行两次，保存源码、修改记录、实际下载文件和指纹。

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 混合已读/未读导出 | 两次状态不一致 | 两次通过 |
| 已读筛选后导出全部记录 | 两次状态不一致 | 两次通过 |
| 刷新后导出 | 两次状态不一致 | 两次通过 |
| 改回未读后导出 | 两次通过 | 两次通过 |
| 新增、状态切换、筛选返回、持久保存及说明页 | 其余 7 条路径各两次通过 | 各两次通过 |

这是同一个导出缺陷在三种情境中的表现，记为 **1 个已知问题、3 条受影响路径**。修改后 11 条路径各两次通过；未发现已覆盖路径回归。净人工省时、返工节省、陌生项目准确性和真人价值仍未测得。

## 判定边界

新增比较器区分：项目不同、标准变化、同版本重复、证据缺失、原问题未修完、新回归、无修改前问题，以及按原标准通过。汇总通过但底层执行不一致时拒绝确认。当前比较器是内部逻辑，输入的 evidenceVerified 必须由调用方核对文件后设置；不能直接暴露成接受客户端声明的接口。
