# 怎样接入自己的产品

公开网站用于体验内置案例。自己的代码在本机接入，不发送到魔搭或 GitHub。

## 第一次启动

1. 从 GitHub 下载并解压验收助手代码，安装 Node.js 22 或更新版本。
2. 在验收助手目录打开终端，依次运行：

```sh
npm install
npx playwright install chromium
npm start
```

3. 打开终端显示的本机地址（默认 http://127.0.0.1:4395），点击 **检查我的产品 / 选择代码文件夹**。

## 选择代码，开始检查

1. 选择自己的网页文件夹。静态 HTML 选择包含 `index.html` 的目录；React / Vue 先按该项目说明构建，再选择输出的 `dist` 或 `build`。ZIP 请先解压。
2. 写目标，例如“检查输入框和手机适配”。需要验证某段文字时，在“页面必须出现的文字”填写明确预期。
3. 点“接入并生成检查计划”，系统在本机保留网页快照，自动启动页面并识别可执行项。首页直接显示本轮可执行项与未覆盖边界，展开查看详细标准，再点“开始这些检查”。
4. 打开报告，核对问题、位置、触发操作、预期与实际记录。
5. 在自己的开发工具修改原代码，然后**重新选择文件夹**接入新版本。原目标和明确文字会保留为可修改草稿；需要比较时保持标准一致。旧快照不随源码更新，单纯重跑旧快照不是修复复检。

## 能检查到什么

| 内容 | 当前行为 |
| --- | --- |
| 入口 | 检查页面主体可见 |
| 明确文字 | 依据用户填写的文字进行比对 |
| 普通输入框 | 目标包含输入或表单时，填写样例并回读；不提交 |
| 手机 / 桌面适配 | 目标包含手机、界面或适配时，检查横向溢出 |
| 支持的报告结构 | 识别可检查的详情与项目内 JSON 证据 |
| 登录、支付、数据库、复杂业务 | 未覆盖，不计为通过 |
| 个人经验与修复收益 | 本轮导入不自动证明历史产生价值，也不计算未经实测的时间或经济节省 |

每项正常检查重复 2 次。网页基础检查通过，不等于整个产品通过。

## 已启动的项目

接入页展开“React / Vue、后端项目或已经启动的页面怎么接入？”，选择“接入已启动页面”，填写本地目录与本机 HTTP 地址。目录必须位于启动时允许的范围内。如需使用其他目录，在验收助手目录运行：

```sh
node v3/workbench.mjs /你的项目目录 4390
```

这会使用用户明确指定的本地目录，仍不执行项目安装或启动脚本。页面必须由用户按项目说明启动；当前仅接受本机 HTTP 地址，不接受公网 URL、登录凭据、查询参数或片段。网络请求严格按当前计划限制，未允许的后端请求会阻止并记录缺项。

使用原目录与运行地址的项目，修改后可输入“重新检查”；使用文件夹选择的快照项目，每次修复后重新接入。跨快照不会自动合并个人经验或给出连续项目收益结论。

## 容量与文件处理

- 每次最多 300 个网页文件，总计 2 MB，单文件 256 KB；与当前扫描预算一致。
- 支持常见网页代码及资源；隐藏文件、依赖目录、常见凭据配置和不支持文件在浏览器端跳过，服务端再次校验。
- 文件名过滤不是完整内容脱敏，请选择已检查的网页构建目录；不选择包含密钥或私人数据的文件。
- 内容只传到当前本机助手，快照和结果保留在 `state` 下；这个目录由 Git 忽略，不自动公开。
- 每次启动最多接入 8 份快照，磁盘最多保留 50 份导入快照；超过时明确提示归档或清理。重启后重新选择网页文件夹以恢复页面服务。
- 不自动安装依赖、不执行后端脚本，也不自动修改用户源代码。

## 修改代码后复检（本地版已发布 GitHub）

完成基础检查后，重新选择修改后的网页文件夹，勾选“这是当前项目的修改版，按原标准复检”。系统带回原目标、输入、预期、范围和次数，再由你开始本轮。检查其他项目保持不勾选。当前仅限基础静态网页任务；[支持范围与核验记录](09-snapshot-repair.md)。

## 上传后会怎样说明范围

首页按实际执行计划列出检查项，不把你填写的整个业务目标当成已经支持。已识别但尚无检查方式的“保存、导出”等目标会直接提示；明确排除项留在详情中，不算失败。若要求检查输入，但没有观察到支持的普通输入框，也会明确提醒。结果为 0 项问题时，仍保留“其他业务流程尚未验证”。全部检查项被移除时，先调整范围，不出现空计划启动按钮。

例如，上传阅读清单并要求“新增、保存并导出”，基础规划可能只有入口检查。页面能打开不能证明新增、保存或导出正确；当前阅读清单业务练习须使用受审的本地启动器，见 [业务复检指引](14-reading-workflow.md)。普通上传不会自动取得该模板的操作权限。

[本轮接入范围核验](20-intake-scope.md)记录三个受控上传场景；未测量真人理解率或人工省时。
