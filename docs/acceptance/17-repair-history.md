# 从当前复检查看上轮问题

日期：2026-09-16。当前结果新增“查看上轮问题与证据”，解决复检通过后还要手动查找旧文件的问题。保持单对话入口，详细内容按需展开。

## 用户怎么做

1. 在本地工作台完成修改后的复检。
2. 点击结果或报告里的“查看上轮问题与证据”。
3. 核对问题位置、触发操作、逐次预期与实际值；需要时下载实际产物、打开结果截图或展开原标准。
4. 点击“回到当前对话”继续当前任务。

页面只读，不切换任务、不执行检查。它展示本次复检所关联的上轮记录，不是全局历史搜索；多轮复检也不表示永远指向最早一次问题。关联仅在本机当前工作台内有效，任务变化后旧链接失效，需从当前结果重新进入。PDF 不增加这些依赖运行中工作台的网页链接。

## 本批核对结果

| 场景 | 核对结果 |
|---|---|
| 同一阅读清单实际修改后复检 | 当前修复结论可打开上轮导出偏差，显示两次预期与实际 |
| 上轮执行结束后再缩小计划 | 历史页面仍用执行时封存的原标准，三条原路径不被后来的计划覆盖 |
| 打开历史页、标准、截图与产物 | 原产物字节一致；当前任务控制状态、活动任务指针和前后任务文件保持不变 |
| 请求其他任务或不允许的文件 | 拒绝；不提供会话、授权身份或原始操作记录文件 |
| 改动上轮实际下载文件 | 历史页与产物入口停止提供已核验内容；当前修复状态变为未确认；恢复原字节后重新核验 |
| 重启本地工作台 | 可信关联保留，仍能查看同一记录 |
| 新建下一轮任务 | 旧页面与旧产物链接失效，不把同名文件混成新一轮证据 |
| 公开演示模式 | 本地验证页面和产物新入口均返回未提供；不是线上部署验收 |

85 项模块测试、7 个实际流程环节通过。前台实际点击了当前结果入口、上轮截图、原标准展开及返回当前对话，截图检查黑白布局可读。产物下载由真实 HTTP 字节比对核验，未据此声称浏览器保存对话框也已测试。

本批业务范围为新增、标记已读、导出三条路径，修复前后各两次，其余八条明确移出本轮。上轮一条导出路径有偏差，实际修改后这三条均通过。此处是导航与证据关联验收，不替代完整 11 条业务路径的复验，不代表陌生项目支持、并发压力测试或真人省时收益。

## 作用与下一步

现在用户能直接核对“原来哪里不符合、当时标准是什么、旧文件是什么”，并回到当前结果继续处理。减少了手动找历史文件这一操作需求，实际节约时间仍未测得，不能据此填写收益百分比。

下一步继续做深当前业务：统一前置失败、执行异常、证据不足和真实产品偏差的显示及后续处理；然后补独立同类迁移证据。任意业务代码上传、跨项目历史检索和真人收益均未在本批完成。

复现：`node audit/check-repair-history.mjs <新的输出目录>`。公开[脱敏摘要](evidence/repair-history.json)保留范围与断言，原任务、文件和页面证据只留本地。代码发布 GitHub；魔搭本地候选待发布，不将仓库提交当作线上更新。
