# 阅读清单：从实际修改到业务复检

日期：2026-09-16。新增本地修复练习入口，使用独立受控副本。原样例、旧任务和下载证据保留。

## 用户怎么做

1. 安装依赖后运行 `npm run start:repair`，打开终端显示的本地地址（默认工作台 4396、样例服务 4397）。已整理好 11 条检查，先查看范围，再点“开始检查”。启动入口不会替你确认开始执行。
2. 查看导出问题和开发交接，修改终端显示的独立副本 `app.js`。本练习的问题是导出映射把所有阅读状态写成 `false`；应保留每本书当前的 `read`。这是本例已知代码修改，不代表任意项目根因能自动确定。
3. 保持该服务和地址，在原对话输入“重新检查”，再点“开始检查”。报告关联前后任务、修改文件、原标准及实际下载结果。只重新运行、没有修改源码，会显示同版本重复检查。

再次运行同一个命令会保留已修改副本和任务记录，不重置故障。更换端口时拒绝混用旧地址的任务；需要另一套练习可指定新的目录：`npm run start:repair -- <新的目录>`。本地状态目录不上传 GitHub。

## 实际验收

| 内容 | 修改前 | 修改后 |
|---|---|---|
| 独立副本及页面地址 | 同一目录、同一地址 | 保持一致 |
| 检查标准 | 11 条冻结路径，各两次 | 标准指纹一致，各两次 |
| 导出当前清单 | 已读记录被写成未读 | 与当前状态一致 |
| 筛选后导出全部书目 | 已读记录被写成未读 | 全部记录及状态一致 |
| 刷新后导出 | 已读记录被写成未读 | 刷新后状态一致 |
| 改回未读后导出 | 符合本例要求 | 仍符合要求 |
| 其他新增、更新、筛选、刷新和说明路径 | 通过 | 未发现已覆盖路径回归 |

这是一处已知导出缺陷，影响三条检查路径，不能算成三处独立根因。前后实际取得 16 个 JSON 下载文件，逐一核对两个书名、记录数量和状态。人工省时、减少返工均未测得。

验证共 76 项模块测试及 9 个实际任务审计环节，覆盖入口只生成计划、客户端不能扩大审核目录、实际源码修改、16 个下载、HTML/Codex 交接、重启保留、下载证据变化撤回通过，以及原样例不变。前台另核对结果、报告展开，以及“重新检查→开始检查”完整执行，结果标为同版本重复检查；最终目录指引与报告展开已做页面核对；未新增 PDF 排版验收。

复现：`node audit/check-reading-workflow.mjs <新的输出目录>`。加 `--inspect` 可保留测试服务做界面检查，用 Ctrl+C 结束。原始执行、截图和交接材料保留本地；[公开摘要](evidence/reading-workflow.json)只包含脱敏案例和必要指纹。

边界：业务目录由本地启动器指定，不能通过网页请求任意扩展。魔搭固定公开演示仍使用原来的 8 条计划，未因此开放任意代码或新增 11 条线上能力。本批不支持任意上传项目自动识别业务模板，也不证明陌生项目迁移或真实用户收益。
