# PDF 业务建议与反馈

日期：2026-09-16。把本地业务建议、用户选择及历史反馈接入实际 PDF 导出，沿用网页与 Codex 交接使用的记录。

PDF 现在包括影响、未知、排查方向、复查条件、逐次操作文件、预期/实际与用户反馈。证据记录按可读标签排版，不直接堆叠整段内部对象。历史反馈明确标为不自动沿用。

| 导出场景 | 实际结果 |
|---|---|
| 有完整导出差异证据 | 建议、根因未知、原标准与操作文件出现在 PDF 中 |
| 用户拒绝建议 | 新文件显示拒绝状态和理由，不复用先前 PDF |
| 重启后已生成缓存，再删除一个实际下载 | 重新生成补证据版本；不保留旧的已确认建议；首页提示历史执行记录不能当作当前结论 |
| 实际修改后按原标准复检通过 | 保留前后版本和原标准，当前故障建议清空；此前拒绝仍作为历史保留 |

导出缓存同时考虑业务建议和反馈历史。生成完成后再次核对任务、复检证据、建议和反馈；期间变化会要求重新下载。本批验证顺序状态变化及重启后的缓存，不声称完成并发压力测试。

验收：82 项模块测试通过；四个实际 PDF 场景通过。四份文件分别 5、5、4、4 页，共 18 页，已进行文字核对、最终字节指纹核对和每页渲染检查。文字提取时对字体映射产生的 CJK 部首字符做规范化，不能把纯文字提取当作排版验收。

**这批专门验证 PDF：只执行新增、标记已读、导出三条业务路径，每条两次，其余八条明确移出本轮。** 不能拿本批三个路径结果替代此前完整 11 路径的验收，也不等于整个产品通过。

用户仍按原流程查看报告并导出 PDF，无需另填指标表。采纳、拒绝、纠正只是选择；人工时间与返工收益继续显示未测得。
