# 复检草稿重启后继续上传

日期：2026-09-16。本批修复文件夹复检中的一个中断点：原任务已完成，用户上传修改版并生成计划，但尚未开始时重启助手。此前本机快照服务停止，页面要求重新选择文件夹，却没有“按原标准复检”的选项。

现在，当前版本创建且未修改、未执行的复检草稿可继续带回原标准。重新选择代码时仍须明确勾选同项目，目标、输入、预期、范围和次数继续冻结。重传多次也只关联原来已完成并保存证据的任务，草稿不会变成已执行的基线。

## 使用步骤

1. 重启后点击“重新选择文件夹”。
2. 选择当前项目的新版本，勾选“这是当前项目的修改版，按原标准复检”。
3. 原要求自动带回；查看计划后开始检查。没有点击开始的草稿不记为已验收。
4. 完成后查看复检结论；“查看上轮问题与证据”仍打开实际执行过的原问题。

如果修改了草稿标准，或者原始证据缺失、变化，不继续声称按原标准复检。旧版本未保存完整草稿关联标记时不猜测恢复；尚未开始的一般新任务也不会被当成修复历史。

## 实际核对

| 场景 | 核对结果 |
|---|---|
| 原版本文字为 Draft，预期 Ready | 入口、明确文字、输入、布局各两次；取得原文字偏差 |
| 修改版生成草稿后重启 | 快照服务停止，但同项目重传入口保留，未产生执行授权 |
| 连续重传尚未执行的草稿 | 原四项标准及两次预算不变，始终关联原已完成任务 |
| 修正文字后真正开始 | 四项各两次通过，源码版本改变、标准指纹相同，原问题复检通过 |
| 新版本删除原输入框 | 原输入检查仍在，执行未完成，整体修复未确认；其他三项各两次通过 |
| 改标准、原证据被改动 | 请求被拒绝，原任务保持；不能用新标准或变化证据代替原基线 |
| HTML、Codex 与历史页 | 保留原已完成任务及同一复检结论，历史页可回查最初两次文字偏差 |

99 项模块测试通过。重启提示及冻结表单的 390 宽度截图已检查，页面无横向溢出；结果页和原历史记录也已打开核对。复现：`node audit/check-snapshot-draft.mjs <新的输出目录>`。公开[脱敏摘要](evidence/snapshot-draft.json)不含原任务标识或本机路径。

本轮只验证受控基础静态网页及原标准延续，没有扩大任意上传项目的业务操作。未验证缺资源的所有情形，也未进行旧版本草稿迁移、任意崩溃点或并发压力验证。HTML/Codex 已核对；本批未重新生成 PDF，不能将此前 PDF 记录当作本批新验收。没有测量真人操作时间，省时继续为未测得。
