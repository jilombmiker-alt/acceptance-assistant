# 产品自身验收与修复记录

本轮先用验收助手自己的规划器检查生成的接入页面，再把实际发现的两条流程要求交给它已有的执行引擎复现和复检。另用实际浏览器完成代码选择、计划生成、执行和旧快照复检提示核验。

## 发现与修复

| 问题 | 用户遇到什么 | 修复 | 复核结果 |
| --- | --- | --- | --- |
| 刷新后首页丢失检查计划 | 任务已经生成，刷新后只剩对话框，找不到开始入口 | 首次加载从服务端恢复当前计划或结果，不依赖浏览器临时标志 | 产品执行器按相同标准各重复 2 次：问题 → 通过；实际页面刷新确认 |
| 帮助错误引导重跑旧快照 | 修改原代码后输入“重新检查”，仍可能检查上次上传的旧代码 | 指引明确重新选择文件夹；快照项目输入“重新检查”只提示接入新版本，不创建旧版本任务 | 指引由产品执行器各重复 2 次：问题 → 通过；实际操作与回归测试确认不重跑 |
| 计划失败后重试重复上传 | 修改目标再次提交会重复建立同一份快照、占用接入额度 | 空白目标在上传前拦截；同一选择在计划失败后复用已导入文件，换文件夹才重传 | API 复现失败位置；回归测试确认重试只上传 1 次、生成计划 2 次 |

同时处理了两个恢复边界：本地服务重启后，失效快照提示重新接入；浏览器不允许保存草稿时，已完成的导入仍能进入检查计划。提交期间锁定表单，避免途中修改目标造成前后不一致。

## 结果

- 2 项固定流程标准，修复前发现 2 项问题，修复后为 0 项；前后标准指纹一致，各重复 2 次。
- 接入页的入口、明确文字、两个普通输入框、桌面/手机溢出共 5 项基础检查，各重复 2 次，修复前后均通过。
- 58 项模块与回归测试通过。
- 实际浏览器已确认代码选择、空白输入错误反馈、生成计划、刷新恢复、执行结果和快照重新接入提示。

基础检查通过仍可能漏掉流程问题。本轮两条流程标准是人工复核后补充给现有执行器的，不能宣称产品已经能自动发现任意使用流程。文件夹操作、异常重试和后端业务的覆盖范围分别保留，没有把未检验项算成通过。
