# 五项缺口的产品闭环

日期：2026-09-16。本批把“代码接入、陌生项目、个人历史、Codex、真实效果”接到同一套任务、检查和证据对象中。完成的是可执行机制和受控自测；需要外部真人或客户项目的数据不伪造。

## 1. 项目代码与完整业务检查

静态网页或构建后的 `dist` / `build` 可在根目录加入 `acceptance.spec.json`。上传后系统自动识别，不再只生成入口、输入和窄屏基础检查，而是校验并执行项目声明的全部业务路径。

契约支持同源页面、填写、选择、点击、刷新、JSON 下载，以及文字、可见性、数量、输入值、溢出和 JSON 结果检查。路径可以声明依赖；移除前置路径会同时移除依赖项。所有操作仍需用户在当前任务开始，限制在隔离的本机快照和明确次数内。

[可复制的示例](../../examples/acceptance.spec.example.json)。`completeContract=true` 表示项目负责人声明这份契约覆盖本次交付目标。系统能完整执行声明范围，但不能只凭这句话证明所有真实需求都已经写入。后端、外部服务、收费、发布、删除、任意文件和主观质量仍需专用适配器。

## 2. 陌生同类项目验证

新增三套未参与编译规则的受控静态项目：任务清单、库存摘要和缺保存按钮的资料表单。每个项目分别携带业务契约，预期答案在执行前固定。

实际执行 3 个项目、6 条路径：6 条与预期状态一致；确定性问题 1 条正确报错，控件缺失 1 条保留未验证，误报 0、漏报 0。该小样本证明契约执行与分类机制，不等于真实客户项目的通用准确率。复现：`node audit/check-independent-contracts.mjs <新目录>`。

## 3. 个人数据持续优化闭环

自动历史原有的“来源 → 适用判断 → 新增检查 → 本轮结果”现在增加跨任务汇总 `/experience-impact.json`。每条来源记录采用任务数、执行路径数、符合、不符合、未验证、停用和最后状态；结果用于决定继续保留、修正或停用。

这个账本证明历史是否实际改变了检查并取得什么结果。没有无历史对照时，它不会宣称个人数据带来省时或因果收益。

## 4. Codex 日常接入

仓库加入项目级 Codex skill：`.agents/skills/acceptance-assistant/SKILL.md`。验收助手运行并已有任务时，在仓库运行：

```sh
npm run codex:context
```

命令只接受 localhost，校验服务返回的内容指纹后把当前目标、冻结检查、问题、证据限制和复检关联直接交给 Codex；不再要求先下载再手工附加。它不安装全局记忆、不读取其他对话，也不静默写入被测项目。需要其他本机端口时设置 `ACCEPTANCE_ASSISTANT_URL`。

## 5. 真实效果数据

原有 A/B 复核器新增从当前任务生成实验标准草稿：

```sh
npm run study -- --init-local http://127.0.0.1:4395 标准草稿.json
npm run study -- --freeze 标准草稿.json 冻结标准.json
npm run study -- --evaluate 冻结标准.json A.json B.json 结果.json
```

它固定完整验收项、主指标、最小改善值、额外时间和费用上限，再比较无历史 A 与有历史 B。最终质量下降、错误套用历史、任务未完成或指标缺证据都会阻止收益结论。真人操作时间、重复解释、返工、绕行、盯守和历史维护成本必须由复核者记录实际证据。

本批验证了标准草稿能从项目完整契约生成，且原有正例、负例和证据缺失反例全部通过。当前仍没有真实参与者，因此真人净省时、成本降低和持续使用保持“未测得”。

## 自行验证结果

- 108 项模块测试全部通过。
- 三套陌生受控项目、6 条实际路径全部与预设答案一致。
- Codex 本机上下文实际读取成功，内容指纹一致。
- 项目完整契约可以生成效果实验草稿；个人历史接口在没有真人数据时返回 `unmeasured`。
- Codex skill 的结构和实际调用已验证。官方 skill 校验脚本因本机 Python 缺少 `PyYAML` 未启动，没有为校验器安装额外依赖。

这些结果完成了五项功能所需的产品机制。真实客户迁移率与真人收益需要外部样本，不能由开发者自测替代。
