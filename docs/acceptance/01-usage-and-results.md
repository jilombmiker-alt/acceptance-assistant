# 验收使用与结果说明

依据已有操作指南、当前公开入口和保存的验收记录整理。本次仅发布说明，不新增功能或重新执行产品验收。

## 公开受控入口

1. 打开 [验收助手](https://modelscope.cn/studios/mlhx0808/acceptance-assistant)，描述目标或点“怎么开始”。
2. 选择内置阅读清单版本，查看计划后开始检查。公开版本不接收任意外部业务目标。
3. 查看问题、位置、触发操作和实际证据；前置受阻与未支持的部分单独列出。
4. 切换正常版本可比较检查结果。两个预置版本的对照不等于开发者实际修改了同一个项目。

## 本地项目

按 [仓库 README](../../README.md) 启动本地入口。只使用主动提供的项目和材料，自动模型连接取决于本地配置。当前执行范围有限，不能由“可输入项目目标”推出“任意业务能自动完成验收”。

本地报告支持查看证据和导出 PDF。PDF 是摘要与文件索引，原始证据需另外保存。模型调用、接口提交和执行次数不直接当作真人操作与返工。

## 结果状态

| 状态 | 含义 | 对后续动作的帮助 |
|---|---|---|
| 符合要求 | 写明范围内有实际结果支持 | 保留版本及证据，继续其他必要检查 |
| 发现偏差 | 预期与实际不一致 | 给出复现步骤和问题包，由开发者定位与修改 |
| 缺证据待判断 | 尚不能取得足够结果 | 先补文件、规则或可信业务状态 |
| 前置受阻 | 必要条件失败导致后续不能执行 | 修复前置条件，独立路径可继续 |
| 未支持 | 当前工具没有可靠执行或判断能力 | 明确缺少的能力，不记为通过 |
| 范围外/不适用 | 本轮排除或未触发适用条件 | 说明原因，不能在失败后改成不适用 |

执行完成是生命周期状态，不代表整个产品通过。影响等级、重复次数和证据充分程度分别记录。

## 产品、助手与用户收益分开评估

| 对象 | 要证明什么 | 当前限制 |
|---|---|---|
| 被测产品 | 约定最终状态、文件及相关功能是否正确 | 结果仅适用于本轮版本和覆盖范围 |
| 验收助手 | 是否误报、漏报或错误归因 | 受控检查不等于通用准确率 |
| 使用收益 | 是否减少实际人工投入和返工 | 尚缺充分真人对照，不填虚构节省值 |
