# 上传代码后的检查范围指引

日期：2026-09-16。本批解决一个接入误解：原首页说“接下来检查你的目标”，实际可能只有页面入口。具体能力虽在详情与报告保留，开始前仍容易把完整业务目标理解为已经支持。

现在直接按实际计划说明本轮检查项；未对应的业务目标和页面观察缺项不会因入口通过而消失。用户不用逐条判断能力，系统给出已有检查方式所能覆盖的范围，详细标准仍折叠展示。

| 情况 | 前台表现 | 本轮验证 |
|---|---|---|
| 上传后要求新增、保存并导出 | 明确本轮仅检查入口，保存与导出尚未对应；其他业务仍未验证 | 真正通过文件选择器上传，入口两次通过后仍保留边界 |
| 要检查输入框，但页面没有受支持的普通输入 | 显示观察缺项，不虚构填写动作 | 实际计划只有入口；此场景未启动执行 |
| 页面具备普通输入，目标包含手机适配，并填写明确文字预期 | 列出入口、明确文字、输入回读、页面尺寸 | 四项各两次通过，390 宽度首页无横向溢出 |
| 将本轮全部检查项移除 | 提示先调整范围，不显示启动按钮 | 真实修改范围并重新打开首页核对 |
| 普通上传目录尝试使用受审阅读清单业务模板 | 服务端拒绝，原任务不被替换 | 实际请求被拒绝；未授权新增业务动作 |

开始按钮改为“开始这些检查”。结果为 0 项问题时仍说明目标中的其他业务流程尚未验证。排除项在详情单独列出，不算失败，也不混入未支持项。三种场景的 390 宽度页面无横向溢出；桌面及移动截图已抽查，维持现有黑白单对话布局。

97 项模块测试通过；本轮三个受控上传流程通过，无捕获的页面脚本错误。公开[脱敏摘要](evidence/intake-scope.json)只保留场景、范围和重复次数，原始任务、源码快照和运行记录只在本地保留。复现：`node audit/check-intake-scope.mjs <新的输出目录>`。

这次调整的是范围说明和空计划入口。没有扩展任意上传代码的业务验收能力，也没有证明陌生用户理解率提升或人工省时；真人收益仍为未测得。检查方式来自现有规则，并不代表完整理解所有自然语言目标。已识别的 JSON 证据路径也不能推导任意业务导出已经通过。

使用顺序：选择网页文件夹 → 写目标 → 查看系统列出的检查项 → 开始这些检查 → 查看证据 → 修改原代码后重传复检。[完整接入指南](04-connect-your-project.md)。GitHub 产品更新与魔搭线上版本分开核对，魔搭仍待发布。
