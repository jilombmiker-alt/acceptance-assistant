# 检查结束但证据未保存完整

日期：2026-09-16。本批延续中断恢复，范围仍为同目录同页面的基础静态网页。

原问题：任务已有完整检查结果，却在证据索引写入前、或索引写入后但任务指纹保存前崩溃。重新打开工作台后，复检一直显示等待。两个位置均在独立测试进程中实际触发终止并复现。

修复后，重启时发现执行已结束但任务没有保存完成的证据指纹，会明确标记“复检证据未确认”，提示保留记录并新建任务。即使磁盘上存在一个孤立的索引文件，也不会直接采用为可信证据。任务记录写入报错时同样撤回尚未保存的成功状态。

| 场景 | 修改前实际观察 | 修改后实际验证 |
|---|---|---|
| 检查结束，索引写入前崩溃 | 结果存在，复检一直等待 | 未确认；原结果字节保持一致 |
| 索引已写入，任务指纹保存前崩溃 | 孤立索引存在，复检一直等待 | 未确认；不自动接受孤立索引 |
| 任务记录写入失败 | 本批未做修改前实测 | 未确认；重新打开后状态一致 |
| 保持目录、页面、原标准，新建任务复检 | 本批新增验收 | 沿用此前有指纹的原问题基线；重新执行完成后通过 |

失效任务仍保留，新的检查不会覆盖其结果文件。后续比较会重新核对原问题基线和新证据的完整性；继承基线不表示略过证据核对。改变标准或源码未变仍沿用既有判定规则，不能算修复成功。

用户只需：重新打开原工作台 → 查看未确认原因 → 保持原要求重新检查。系统保留失败记录，处理原问题关联；无需用户逐项填评审表。这里的新任务必须仍使用同目录与同页面；不同上传快照的恢复关联不在本批支持范围内。

验证：74 项模块测试通过；三个实际故障注入场景各包含六项核对，覆盖原始结果保留、状态/JSON/HTML/Codex 交接一致、再次重启以及新任务重验。每个案例的基础检查为 3 条，每条两次。另复跑上一批 9 个中断恢复环节，确认正常暂停继续、恢复后封存、源码变化拒绝、证据篡改拒绝和下一任务关联仍正常。

复现：`node audit/check-seal-crash.mjs <新的输出目录>`。`--observe` 仅观察当前行为，不表示修复通过。写入失败和终止逻辑仅注入审计脚本自己的子进程，产品没有故障开关。原始运行与授权文件仅保留本地；[公开摘要](evidence/incomplete-seal.json)经过脱敏。

这次没有自动补签丢失的证据，也没有证明任意崩溃时刻、断电文件系统一致性、任意后端或上传服务恢复。未新增 PDF 排版与完整前台操作验收。人工省时、返工和独立项目准确率仍未测得。
