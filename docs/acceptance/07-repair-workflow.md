# 本地任务与报告的复检关联

日期：2026-09-16。本批已本地验证，尚未发布。

同一代码目录、同一页面地址的新任务会关联上一轮已保存的证据。系统在开始前复制本轮已扫描源码，在结束后记录计划、运行结果、逐次记录、截图及实际下载文件的指纹。报告每次读取关联结果时重新核对文件，客户端声明“已验证”不能代替服务端证据。

用户修改原目录代码后，在原任务输入“重新检查”，核对本轮计划并开始。对话显示复检结论，HTML 报告可展开修改文件、前后程序版本和标准，并下载 `/repair-comparison.json`。版本指纹仅覆盖实际扫描文件，不代表完整产品或远端部署。

| 核验场景 | 实际结果 |
|---|---|
| 首次检查 | 不编造前次任务 |
| 同目录实际修改、原文字标准不变 | 原问题重复通过，关联前后任务 |
| 助手重启 | 原关联保留 |
| 修改前证据被改动 | 撤回确认，显示证据未通过核对 |
| 原始文件缺失/产物变化 | 文件核对拒绝；有模块反例 |
| 程序没有变化 | 标为同版本重复检查 |
| 文字标准变化 | 标为标准改变，不声称原问题修复 |
| 对话、HTML 与 JSON | 真实浏览器和本机接口已核对 |

验证：64 项既有及比较器测试通过，新增 2 项证据存储/呈现测试通过；真实本机工作台 7 个场景通过。当前完整实测为受控文字要求修复，不能替代阅读清单的用户级自动关联验收、陌生项目迁移或真人收益。此前阅读清单 11 条路径的连续修复仍是独立开发者审计案例。
